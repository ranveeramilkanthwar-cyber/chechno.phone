1. Indian Data Leak Vectors & DPDP Act 2023 Legal-Technical Mapping
Unlike Western data broker ecosystems that rely primarily on static people-search sites (such as Spokeo
or Whitepages), personal data exposure in India operates through five high-velocity commercial
pipelines. Designing an automated removal platform for India requires specialized discovery adapters
and statutory erasure payloads tailored to each vector:
DSA Personal Loan & Credit Card Syndication Pools: Direct Selling Agents (DSAs) and fintech lead
aggregators exchange CSV dumps and real-time webhook leads containing +91 phone numbers,
approximate CIBIL score bands, city PIN codes, and salaried status.
Local B2B & Consumer Directories: Platforms such as Justdial, IndiaMART, Sulekha, and TradeIndia
index personal mobile numbers alongside proprietor or inquiry records, making them scraping targets
for telemarketers.
Caller-ID & Contact Graph Aggregators: Crowd-sourced address book uploads expose full names,
carrier circles (e.g., Airtel Maharashtra, Jio Mumbai), and email mappings.
Real Estate & Classified Portals: Property inquiry forms on 99acres, MagicBricks, Housing, and Quikr
syndicate buyer phone numbers to dozens of regional brokers simultaneously.
Statutory & Public Gazette Records (Non-Removable Category): Ministry of Corporate Affairs
(MCA) DIN master data, state government gazettes, and Electoral Roll summaries are exempt under
Section 3(c)(ii) of the DPDP Act 2023 and must be transparently flagged as Not Removable /
Statutory Public Record in the UI.

3.1 Shared Cross-Platform Sync Engine (`packages/sync-engine/src/usePrivaSync.ts`)
When a user checks or unchecks a data broker listing on the mobile app—or clicks Authorise Removal
on the desktop web dashboard—the isomorphic sync hook applies an immediate optimistic UI update
and broadcasts a signed state delta across all connected devices in under 50 milliseconds:

import { useEffect, useRef, useCallback } from 'react';
import { useQueryClient } from '@tanstack/react-query';
export interface SyncEventPayload {
  event_type: 'SCAN_PROGRESS' | 'CONSENT_TOGGLED' | 'REMOVAL_DISPATCHED' | 'STATUS_VERIFIED' | 
'HEALER_PATCHED';
  scan_id: string;
  broker_id?: string;
  status?: 'EXPOSED' | 'PENDING' | 'REMOVED' | 'NOT_REMOVABLE';
  selected?: boolean;
  progress_step?: number;
  timestamp: string;
}
export function usePrivaSync(userId: string, jwtToken: string, wsBaseUrl: string) {
  const queryClient = useQueryClient();
  const wsRef = useRef<WebSocket | null>(null);
  const reconnectTimer = useRef<ReturnType<typeof setTimeout> | null>(null);
  const connect = useCallback(() => {
    const url = `${wsBaseUrl}/v1/ws/sync?
user_id=${encodeURIComponent(userId)}&token=${encodeURIComponent(jwtToken)}`;
    const socket = new WebSocket(url);
    wsRef.current = socket;
    socket.onmessage = (event) => {
      const payload: SyncEventPayload = JSON.parse(event.data);
      // Deterministically update TanStack Query cache across both Next.js Web & Expo Mobile
      queryClient.setQueryData(['exposures', payload.scan_id], (oldData: any) => {
        if (!oldData) return oldData;
        return {
          ...oldData,
          progress_step: payload.progress_step ?? oldData.progress_step,
          listings: oldData.listings.map((item: any) =>
            item.broker_id === payload.broker_id
              ? {
                  ...item,
                  status: payload.status ?? item.status,
                  selected: payload.selected ?? item.selected,
                  updated_at: payload.timestamp,
                }
              : item
          ),
        };
      });
    };
    socket.onclose = () => {
      reconnectTimer.current = setTimeout(connect, 1500);

4. System Architecture & Database Schema (PostgreSQL 16 + pgcrypto)
Because PrivaIndia handles sensitive Indian personal identifiers (+91 phone numbers, email addresses,
full names), storing raw plaintext PII in standard database columns would create an unacceptable
honeypot risk. Our PostgreSQL architecture implements Dual-Layer Cryptographic Isolation:
1. Blind Indexing for Lookups (HMAC-SHA256 + Argon2id): Phone numbers are normalized to E.164
(+919820471920) and hashed with a Rotating Server Pepper stored in AWS KMS (ap-south-1
Mumbai). This allows O(1) indexed lookups without exposing raw numbers.
2. Ephemeral Envelope Encryption (AES-256-GCM): The encrypted contact payload is decrypted
exclusively in volatile worker memory during active scan or DPDP erasure notice dispatch, and is
purged immediately upon task completion.
